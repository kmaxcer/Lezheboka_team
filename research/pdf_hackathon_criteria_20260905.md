## Цель и автоматическая метрика

Кейс состоит из двух связанных задач: (1) восстановление скрытых значений `primary_ndvi` в контрольных пропусках; (2) детекция и интерпретация аномалий в веб-интерфейсе. Автоматически оценивается только задача 1.

Для контрольных точек:

`RMSE = sqrt((1/N) * sum((y_true - y_pred)^2))`.

Командный GapScore:

`round(30 * max(0, 1 - RMSE_team / 0.10), 2)`.

RMSE >= 0.10 дает 0 баллов, RMSE = 0 дает 30. Примеры из задания: 0.08 -> 6, 0.05 -> 15, 0.02 -> 24, 0 -> 30. Поэтому снижение RMSE напрямую дает до 30 из 100 экспертных баллов.

## Данные и leakage-правила

Сначала выдаются `train_dataset.csv` (99 955 строк с известными `primary_ndvi`) и `private_features.csv` (тестовые строки). Одна строка соответствует анонимному полигону и дате, ключ — `anon_polygon_id + date`. В наборах встречаются Sentinel-2, Landsat, MODIS, ERA5, календарные `year`/`day-of-year`, `primary_ndvi`, характеристики климатической нормы, `n_reference_years`, `is_synthetic_gap` и статичный `crop_type`.

В private для строк `is_synthetic_gap=True` скрываются `primary_ndvi`, динамические и вычислимые признаки. Восстанавливать нужно только такие строки; естественные пропуски сами по себе контрольными точками не являются. Ground truth организаторы не выдают.

`submission.csv` формируется только для `is_synthetic_gap=True`, содержит ровно:

`anon_polygon_id,date,primary_ndvi_pred`

`date` — `YYYY-MM-DD`; ключ должен встретиться ровно один раз и совпадать с контрольной строкой private. Запрещены пропуски, `NaN` и `Inf`; CSV с запятой, UTF-8.

Практическое следствие: локальная проверка должна имитировать synthetic-gap masking на известных train-строках, не использовать замаскированные dynamic/sensor поля для gap-строки и обязательно разделять проверку по полигонам/регионам и сезонам. Для переноса на новые территории рекомендуются holdout по полям или целым сезонам вне обучения.

## Рекомендуемый научный протокол из постановки

Минимальный baseline для одиночного пропуска — среднее двух ближайших известных значений до/после даты. Допустимы линейная/сплайн-интерполяция, Savitzky–Golay, Whittaker smoother, модели временных рядов и ML.

Для аномалий предложена климатологическая норма:

`Z = (NDVI_fact - NDVI_climatology_mean) / NDVI_climatology_std`.

Интерпретация: `Z >= -1` — штатное развитие; `-2 <= Z < -1` — угнетение биомассы; `Z < -2` — критическая аномалия. Более сильное решение должно сопоставлять NDVI с температурой/осадками ERA5/ERA5-Land, другими индексами и соседними датами, отделяя погодный стресс от выбросов, облаков, смены фазы и ошибок данных.

Рекомендуемые открытые источники для расширения: Sentinel-2 SR (COPERNICUS/S2_SR_HARMONIZED), Landsat 8/9 Level-2, MODIS NDVI/EVI (MODIS/061/MOD13Q1), ERA5-Land hourly, ESA WorldCover/WorldCereal и OpenStreetMap/Overpass API для контуров.

## Что максимизирует общий результат

1. Метрика: прежде всего снижать leakage-safe RMSE на synthetic gaps; при равных моделях выбирать устойчивую к новым AOI/2025 конфигурацию.
2. Исследование: зафиксировать baseline, маскирование, несколько seed/cohort/year/source/distance с таблицами и объяснением, почему финальная формула выбрана.
3. Техническая часть: обеспечить batch-инференс для private и веб-сервис с выбором/рисованием полигона; отображать исходный и восстановленный `primary_ndvi`, найденные аномалии и объяснение через климатическую норму/погоду.
4. Воспроизводимость: README с командами, зависимостями, seed, источниками и путями входа/выхода; модель/веса и конфиги доступны без ручных правок.
