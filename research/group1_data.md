# Группа 1 — аудит данных и ошибок

## Проверенные файлы

Использованы `train_dataset.csv` и `private_features.csv` из скачанного задания (оригиналы в Downloads не изменялись).

- train: 99 955 строк, 39 AOI, 2010-04-01 — 2024-10-30;
- private: 57 185 строк, 78 AOI, 2010-04-01 — 2025-10-30;
- контрольных строк `is_synthetic_gap=True`: 3 112;
- дубли ключа `(anon_polygon_id, date)`: отсутствуют.

На контрольной строке замаскированы все динамические поля, поэтому модель должна использовать только дату, AOI, crop_type и соседние наблюдаемые `primary_ndvi`.

## Ошибки и риски

1. Пропуски сенсоров очень велики: S2 около 86–89%, Landsat около 84–86%, MODIS около 92–93%. Нельзя требовать конкретный сенсор.
2. Приоритет исходного target подтверждён: S2 → Landsat → MODIS. В train и private observed `primary_ndvi` совпадает с первым доступным сенсором.
3. Есть выбросы вспомогательных рядов (`s2_evi` порядка 1e11, Landsat NDWI до ~18) и единичные аномальные значения target. Нужны finite-фильтр, робастная регрессия и clip итогов.
4. Синтетические даты часто совпадают между AOI и являются не случайной ежедневной маской. Соседние календарные строки могут быть естественными пропусками, поэтому искать ближайшие **наблюдаемые target**, а не просто соседнюю строку.
5. В private у synthetic-строк `year/doy` пусты; их обязательно пересчитывать из `date`.

## Проверка текущего baseline

`src/infer.py` запускается на реальных данных и выдаёт ровно 3 112 строк в требуемом формате. Локальная псевдо-валидация по private-подобным датам:

| год | n | RMSE |
|---:|---:|---:|
| 2019 | 249 | 0.07252 |
| 2020 | 222 | 0.06849 |
| 2021 | 130 | 0.10082 |
| 2022 | 192 | 0.07632 |
| 2023 | 169 | 0.08196 |
| 2024 | 152 | 0.07075 |

После seasonal sensor-map и same-year/date prior патчей полный средний уровень
стал ~0.071 RMSE (исходно ~0.079); 2021 остаётся самым сложным годом
(~0.090), а edge/длинные пропуски — главным остаточным риском. Baseline
использует локальную робастную линейную интерполяцию в том же AOI+году,
source-calibration и fallback по AOI.

## Рекомендации для следующей итерации

- Оставить локальную интерполяцию главным методом.
- Для отсутствия левого/правого наблюдения добавить сезонный fallback (AOI по другим годам, затем crop+DOY), с clipping в [-0.5, 1.2].
- Валидировать масками, совпадающими с private по AOI и DOY; отдельно считать singleton, multi-day и edge gaps.
- Не обучать модель на замаскированных auxiliary features: на private их нет.
- Исправлен `src/validate.py`: пути к данным задаются через `--train/--private`, по умолчанию указывают на рабочую папку данных.
